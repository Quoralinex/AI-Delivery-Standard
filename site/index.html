Why it exists

Prompts are history. Delivery packages are infrastructure.

AI systems can produce excellent software, research and operating systems, but a chat transcript is a poor reconstruction mechanism. ADS crystallises the delivered state: what was built, where it runs, how it was configured, how it is verified, and exactly how to rebuild it.

How it works

Close out the project, not just the conversation.

1

Discover

Inventory the active session, earlier project sessions, files, repositories and deployment evidence. The current conversation is never automatically treated as the complete project.

2

Reconcile

Identify delivered, already-packaged, superseded and missing items. Incomplete source coverage prevents a false completion claim.

3

Package

Generate the human manual, machine execution specification, architecture and deployment inventories, evidence, rollback record, SBOM and checksums.

4

Verify

Validate schemas, acceptance evidence and archive integrity. Delivery closes only when the selected completion profile passes.

Architecture

A discovery hierarchy any capable executor can follow.

Project catalog→Project delivery index→Delivery manifest→Rebuild execution spec→Evidence

Human-readable

Manuals explain the design, architecture, operation, deployment and recovery decisions.

Machine-readable delivery

JSON Schema contracts define the state and ordered execution stages so a future model does not need to reinterpret a narrative prompt.

Portable adapters

The normative core is provider-neutral. Adapters show how OpenAI, Claude, Codex, Qwen, Gemini and generic desktop AI environments consume it.

Retrospective closeout

Recover projects that span multiple chats.

ADS supports current delivery and retrospective project reconstruction. It inventories existing packages first, then searches all accessible project history before generating missing closeouts. If known sources cannot be accessed, the source ledger says so and closure fails closed.

Portability

Designed for the next model, not the current one.

Host-dependent values are discovered or parameterised rather than assumed. The same specification can move between Intel and Apple Silicon Macs, Windows, Linux, local models, cloud models and multimodel orchestrators as long as the execution host exposes the required capabilities.
